# Порядок подій, невдалі маршрути та самостійний найм

Реалізація: 18.09.2026. Покриває M1–M3 у STATUS_AUDIT.md на рівні коду.

## Поведінка

- Прибуття реєструє спробу. FinishWork, FinishShopping та FinishDay
  виконують відповідні дії у спільному порядку: список мешканців зі зсувом
  `день % кількість мешканців`. Черга щодня змінюється.
- Зарплати, виробництво, покупки та їжа не залежать від порядку кадрів.
  Угоди зерна та виплата прибутку залишаються між відповідними фазами.
- ReportUnreachable завершує одну невдалу спробу. Повтор відхиляється.
  Недоступна робота не дає зарплати чи виробництва; недоступна крамниця
  не виконує покупку; недоступний дім означає пропущений прийом їжі
  зі збереженням інвентарю. Решта поселення продовжує день.
- 3D використовує таймаут 30 секунд активного руху; пауза не витрачає його.
  Є тестові перемикачі Block farm та Block bakery / shop.
  Обходу перешкод і визначення шляху через NavMesh ще немає.
- На початку дня безробітні шукають вакансії. Вища зарплата має пріоритет,
  за рівності — ordinal ID бізнесу. Роботодавець має фінансувати хоча б
  одну зарплату, а вакансія повинна бути вільною. Найм виконується послідовно
  у щоденній черзі та не створює грошей. Відстань і навички ще не враховуються.
- Без вакансії NPC повторює пошук завтра. При невиплаті працівник зберігає
  посаду, не виробляє сьогодні та повторює спробу наступного дня.
  Причини записуються до журналу та показуються у вибраного NPC.
- XML v3 зберігає режим автономного найму та лічильники невиплат/маршрутів.
  Причини рішень відновлюються з журналу. XML v1/v2 підтримуються,
  автоматичний найм для них вимкнений, щоб зберегти попередній ручний режим.

## Перевірка в Unity, яка ще потрібна

1. Вийти з Play Mode, виконати Assets/Refresh, відкрити MainSimulation.
2. Job search demo → Next day: два безробітних займають доступні посади;
   у вибраного NPC видно Decision.
3. Block farm або Block bakery / shop → Next day: день завершується,
   failed routes збільшується, пропущені дії не створюють грошей.
4. Pause walking не породжує таймауту. Після продовження день завершується.
5. Save завершеного дня → вихід/повторний Play → Load: відновлюються
   посади, режим найму, журнал та діагностика.

M1–M3 реалізовані й перевірені в ядрі. Повний перехід етапу потребує
ручної перевірки Unity UI, перезавантаження скриптів та підтвердження backup.
Наступна механіка — економічні звіти: розподіл грошей, голод, невиплати
й запаси; після цього конкуренція/інші фактори по одному за ROADMAP.md.
