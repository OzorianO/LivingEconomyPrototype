# M1a — спільний інвентар

18.09.2026. Перший підетап M1; це не завершення всього M1.

## Реалізація

- `ItemDefinition` / `ItemCatalog`: незмінні визначення, ordinal ID `grain` і `bread`.
- `ItemInventory`: кількість за ID, максимальна загальна кількість та кількість слотів.
  Grain: 100 одиниць на стек; Bread: 20. Стеки агреговані, не мають окремих ID.
  Зайняті слоти = сума округлених догори quantity/maxStack для кожного предмета.
- Resident і бізнес-рахунок використовують цей самий тип сховища. `Stock(Good)`
  та старий `Inventory[Good]` — живі проєкції, не дубльовані запаси.
- `Items` — справді read-only обгортка; повернений об'єкт не можна привести
  до mutable ItemInventory. Словник quantities також read-only.
- Торгівля, виробництво та їжа змінюють єдине сховище. `Economy.TransferGoods`
  переносить товари без платежу, журналює успіх/відмову. Купівля залишається `Buy`.
- `TryTransfer` перевіряє доступ, різні сховища, однаковий об'єкт каталогу,
  предмет, кількість, запас, переповнення і місткість до будь-якої зміни.

## Межі та інтеграція

Це синхронне ядро симуляції, не захист від недовіреного клієнта. `accessGranted`
передає результат перевірки дозволу з довіреного сервісу команд. Контролер/UI
не повинен сам вирішувати, чи можна брати чуже майно. Власність і generic actions
розвиваються в M1b; смерть і loot — M1c/M9. `TryAdd`/`TryRemove` — довірені
операції для створення/споживання, не автоматично дозволені дії героя.

Поточні NPC/бізнеси зберігають практично необмежену місткість, щоб не змінити
баланс M0 і не втратити старі запаси. Контейнери з обмеженнями перевірені в тестах.
Реальний герой у сцені ще не підключений: тестовий agent `hero-test` доводить
спільність API, а не готовий gameplay героя.

XML v3 залишається без змін: Grain/Bread зчитуються з того самого сховища,
старі v1/v2/v3 продовжують завантажуватися. Довільні предмети/контейнери та їх
місткість не серіалізуються v3; нова схема Save і міграції належать M1c.
Нові типи ресурсів додаємо лише разом із потрібними командами та Save-підтримкою.

Пакети не встановлювалися. Навігацію, камеру та генератор острова підключатимемо
через адаптери до команд/представлення, не через незалежну другу економіку.
Спільний інвентар не потребує Unity API та придатний для headless тестів.
