## M1a — Спільні предмети та інвентар

- [x] Визначити ItemDefinition / каталог зі стабільними ID; почати з Grain і Bread.
- [x] Спільний Inventory для агента, контейнера та бізнесу: quantity, stack, місткість.
- [x] Атомарне перенесення: перевірка кількості, доступу і місткості до зміни обох сторін.
- [x] Визначити одне джерело істини для запасів: не вести паралельно Economy.Stock та Inventory без узгодженої моделі.
- [x] Адаптувати існуючі NPC та бізнеси без втрати запасів і регресії старої економіки.
- [x] Перевірити перенесення між NPC, контейнером і бізнесом; відмова не змінює стан.

Реалізація та межі: [M1_INVENTORY.md](M1_INVENTORY.md). Ядро: 31 103 твердження,
з них 3 045 нових перевірок інвентарю; це не кількість окремих сценаріїв.
На момент M1a герой у сцені ще не мав гаманця/інвентарного UI;
підключення вже виконано в M1b, див. нижче.

**Результат M1a:** спільний inventory/API використовується не лише героєм;
підтверджено відсутність втрат, дублювання та часткових операцій.

## M1b — Герой у тій самій економіці

- [x] Ідентичність агента, account/wallet ownership та правило походження стартових коштів героя.
- [x] Generic action/command API; Player і NPC обирають дію через різні контролери.
- [x] Спільні hunger і thirst; відображення потреб, consume action.
- [x] Купити Bread у Bakery через атомарну транзакцію Economy.
- [x] Передати Bread до спільного інвентарю та спожити один раз для зменшення hunger.
- [x] Перевірити нестачу грошей/товару/місця та збереження загальної суми грошей.

Докладно: [M1_HERO_ECONOMY.md](M1_HERO_ECONOMY.md). Звичайний старт героя —
0 монет; окрема developer demo передає 12 монет з особистого рахунку власника.
Гаманець/товари/потреби героя вже включено в XML v4, щоб M1b не втрачав майно
через Load; позиція, lootable/death та камера ще належать M1c.

**Результат M1b:** герой купує і споживає реальний товар; NPC може виконати
той самий command. Вода та повний survival-цикл розвиваються у M3.

## M1c — Збереження, стани агента й базова камера

- [x] Save/Load ID, account, Grain/Bread, needs і позиції героя (XML v5).
- [x] Розширити Save/Load для нового dead/lootable стану (XML v6).
- [x] Визначити нову версію формату та міграцію XML v1/v2/v3/v4 без вигаданого майна.
- [x] Ядро переходу агента в мертвий/lootable стан: його предмети та особисті кошти залишаються доступними.
- [x] Перенесення з тіла/контейнера без повторного loot, дублювання та нарахувань померлому.
- [x] Відокремити особисті кошти від бізнес-рахунків; визначити поведінку бізнесу без власника.
- [x] Базова first-person камера; дорога модель/анімації та фінальне перемикання належать M12.
- [x] Цільова регресія ядра та Unity; Windows Save/Load після перезапуску процесу, включно з переходом від legacy шляху LivingEconomyPrototype до Medieval Colony.

M1c ще не є бойовою системою: health/damage, зброя, полювання і бандити — M9;
respawn — M3, спадкоємці — M10. Правило збереження майна закладається раніше.
**M1 DONE:** закрито M1a–M1c і критерії Gate M1 в основному roadmap.

Перша контрольна точка M1c — позиція та камера: [M1_HERO_POSE.md](M1_HERO_POSE.md).
Друга контрольна точка — [смерть/loot і призупинений бізнес](M1_DEATH_LOOT.md).
Регресія ядра (31 204 твердження) та Unity (215 lifecycle checks) пройшла; Windows process-restart і legacy migration підтверджені вручну 19.09.2026.
**M1c і M1 DONE.** Реальні нові світові контейнери й додаткові
ресурси потребуватимуть розширення Save разом із появою їх у наступних етапах.
