# Перевірки майбутнього ядра

- Успішна покупка: покупець втрачає рівно ціну, продавець отримує її;
  товар переходить у потрібній кількості, загальна сума монет стала.
- Недостатньо коштів або товару: відмова без часткових змін.
- Нульова/від’ємна кількість, невідомий товар, переповнення суми: відмова без змін.
- Зарплата: переказ лише наявних коштів роботодавця; за браку — явна відмова.
- Випічка: витрачено зерно, створено хліб за рецептом; без сировини немає випуску.
- Споживання: зменшує лише наявний хліб та відповідно змінює голод.
- Однаковий seed і сценарій дають однаковий журнал.
- 30 днів: після кожного кроку сума монет стала, рахунки й запаси невід’ємні;
  звіт показує доходи, голод, запаси та причини невдалих угод.
- 100 днів: перевірити концентрацію коштів, неплатоспроможність бізнесів,
  доступність роботи та частку голодних. Це перевірка балансу, не лише коду.
- Збереження/відновлення, коли реалізовано: продовження дає той самий результат,
  що й безперервний запуск, включно з випадковістю.

Сценарії ще не автоматизовані й не виконані: коду симуляції наразі немає.
