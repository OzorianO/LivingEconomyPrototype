# Стабілізація: Windows-збірка та перевірки

18.09.2026. Контрольна версія перед роботою: f6213be.

## Виправлення

- EditorBuildSettings запускає MainSimulation замість SampleScene.
- Команда Unity `Living Economy/Build Windows` перевіряє список сцен і створює
  development-збірку `Builds/Windows/LivingEconomyPrototype.exe`.
- Перша збірка виявила `Value cannot be null. Parameter name: shader`:
  матеріали створювались через Shader.Find, а потрібний шейдер вилучався зі збірки.
  Тепер матеріали клонуються з Resources/IslandSurface.mat, включеного до збірки.
- GitHub Actions запускає тести економіки з .NET 10 на push і pull request.
- ROADMAP і TASKS узгоджено з фактичним станом; нові механіки відкладені до стабілізації.

Збірку виконано в окремій перевірочній копії з кешем Unity. Нові локальні
зміни QualitySettings і Assets/_Recovery основного проєкту не змінювались
і не включались у перевірочну копію. Це перевірка контрольної конфігурації,
а не підтвердження всіх локальних налаштувань редактора.

## Перевірка збереження

Перевірку Save/Load завершено після зникнення запиту брандмауера:
Run 30 days → Save (XML v3, Tick=30) → повне завершення процесу → новий запуск
(день 0) → Load (день 30) → Run 30 days (день 60) → Save.
На днях 30 і 60: paid=18/18, fed=20/20, bread=20, coins=1642/1642,
hungry=0, failed routes=0. Перевірено через справжні кнопки Windows-гри.
Початковий користувацький settlement.xml повернуто з резервної копії;
відновлення підтверджене збігом SHA256. Тестові XML та скріншот збережено локально.

Попередній журнал Windows-гри містив повідомлення URP про вилучені/непідтримувані
GaussianDepthOfField, BokehDepthOfField і PaniniProjection. Вони не завадили
перевіреному циклу, але ці ефекти постобробки не виконуються; їхню конфігурацію
виправлення підтверджено нижче. Це не виправлена раніше відсутність основного матеріалу острова.

Результати подальших виправлень і розділення коду описано нижче.

## Відтворення збірки

Відкрити проєкт Unity 6000.6.1f1 з установленим Windows Build Support.
Вийти з Play Mode і вибрати `Living Economy > Build Windows`.
Запускати exe разом із усією папкою Windows; один exe без Data та DLL не працює.
Результат записується у `Builds/Windows/build-result.txt`.
Development-збірка призначена для тестування, а не публічного релізу.

## Завершення поточного етапу

SettlementView розділено на IslandGenerator (геометрія), OverviewCameraController
(оглядова камера), NpcMovementView (фази і маршрути) та SettlementSelectionView
(вибір та інформація). SettlementView лишається точкою ініціалізації, зв'язку
компонентів і керування життєвим циклом ресурсів. Серіалізовані поля ракурсу
залишено у view для відновлення після reload. Розділення зафіксоване в 7610179.

Безробітні сірі, власники зелені, працівники ферми сині, пекарні жовті;
голод має пріоритет і показується червоним. Робочі ряди рахуються окремо
для кожного бізнесу й розташовуються перед стінами.

Остаточна Unity-регресія: PASS, 179 перевірок (43 нових твердження про кольори
та робочі позиції). Виключених пошукових помилок: 0. Ядро: PASS 28 058.

У ресурсах URP вимкнено вилучення невикористаних ефектів постобробки, оскільки
renderer створював відповідні проходи, а shader stripping робив їх непридатними.
Нова Windows-збірка: Succeeded, errors=0, warnings=2, bytes=176438697.
Ціна виправлення — приблизно 3 МБ додаткових ресурсів.
Новий журнал запуску не містить попередніх повідомлень DepthOfField/Panini,
помилок чи винятків у перевірених сценаріях.

Два попередження BuildReport: Hidden/Core/DebugOccluder і DebugOcclusionTest.
Обидва штатні службові шейдери пакета Core мають тег HDRenderPipeline,
тому вилучаються з URP-збірки. Це не матеріали острова і не ефекти його камери.
Не змінювали код пакетів і не додавали HDRP лише для приховування цих попереджень.
BuildWindows тепер записує повний текст попереджень у build-result.txt.

У справжньому exe після розділення коду перевірено: інформаційна взаємодія
героя, огляд острова, вибір пекарні, базові 30 днів, дефіцит їжі, відсутність
капіталу й найм двох безробітних. Кризові сценарії показали голод/невиплату,
сума грошей лишилась 1642; найм відновив 18 працівників і 20 нагодованих NPC.
XML-слот під час цих додаткових перевірок не змінювався.

Перевірка Save/Load після закриття процесу описана вище і виконана до
розділення presentation; економічне ядро та XML-код не змінювались.
