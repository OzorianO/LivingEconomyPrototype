# Відновлення UI та симуляції після перезавантаження скриптів

Дата: 18.09.2026. Підтримка в SimulationPreview, SettlementView,
SimulationSave та ReloadCheckpoint. XML-збереження гри залишається v3.

## Правило відновлення

UI зберігає XML-контрольну копію завершеного дня у серіалізованому полі
MonoBehaviour. Вона оновлюється до початку наступного дня, після завершення
дня, ручної зміни роботи, Reset/Load і швидкого проходження 30 днів.
OnDisable під час перезавантаження пам'ятає завершений стан або позначає
перерваний день. OnEnable відновлює чисте ядро й перебудовує поселення.
Awake більше не є єдиною точкою ініціалізації.

Якщо перезавантаження перервало день, виконані в ньому зарплати, виробництво,
найм і покупки відкочуються до контрольної копії. Auto days зупиняється;
повідомлення пояснює відновлений день. Next day починає перерваний день заново.
Це не збереження посеред маршруту: незалежні маршрути ще не серіалізуються.

Пошкоджений знімок викликає видиму помилку з кнопкою Start new session,
замість прихованої втрати стану. Дисковий слот при відновленні не перезаписується.
Для першого завантаження цієї зміни поверх попередньої версії, яка не мала
контрольної копії, збережений у RAM стан недоступний; попередній дисковий Save
можна завантажити кнопкою Load.

## Об'єкти карти

Усі нові створені об'єкти згруповані під GeneratedSettlement. При відновленні
старий корінь вимикається одразу, видаляється разом зі своїми матеріалами,
потім створюється один новий. Старий формат прямих дочірніх примітивів
мігрується за відомими назвами на спеціальному об'єкті SimulationPreview.
Інші об'єкти сцени не очищаються. Камера, створена поселенням, також є дочірньою
цього кореня; наявна камера сцени використовується без видалення.

Повторний Initialize не дублює карту; компоненти мають DisallowMultipleComponent.
Запуск Play перевіряє наявний preview та починає свіжий сеанс. Додаткові preview
вимикаються зі своєю створеною картою. Новий Play починає день 0, Load
відновлює збережений день. Захист Update/OnGUI не виконує дії до готовності UI.
Вибір NPC й тестові блокування після перебудови очищаються.

## Перевірки

Ядро: PASS, 28 058 тверджень. Додано знімок із Unicode-іменами та зміненою
роботою, відновлення точного журналу, відкат частково виплачених зарплат,
повтор дня без подвійної виплати, оновлення завершеної контрольної копії,
відмову без базового знімка, пошкоджений XML і заборону DTD.
Ядро та 3D-код компілюються проти Unity DLL без помилок/попереджень.

Додатковий Editor-тест знаходиться у
Implementation/Editor/ReloadLifecycleVerification.cs й виконується лише
в окремій копії .Verification/UnityReload-20260918-a. Він не переноситься
в основний проєкт. Unity 6000.6.1f1 у batchmode/nographics: PASS,
20 lifecycle-перевірок. Реально виконано два Domain Reload: перерваного
та завершеного дня, точне порівняння стану й журналу, 3D-день із заблокованою
фермою, повторний Play з поточними вимкненими Domain/Scene Reload і Load
контрольної копії. Один preview, один SettlementView і 20 капсул перевірено
на кожному переході. Дисковий слот основної гри не використовувався.

Перший холодний запуск завершився стороннім збоєм UnityEditor.Search під час
побудови індексу. Повторний тест відсікав тільки цей конкретний стек; два
таких повідомлення залишилися в логах, усі інші Error/Exception провалювали тест.
Початковий невдалий результат збережено у .Verification/first-lifecycle-result.txt.
Підсумкові докази: .Verification/UnityReload-20260918-a/lifecycle-result.txt
та verification.log. Візуальне відображення панелі/миші не перевіряли: тест
без графіки перевіряє життєвий цикл, дані, об'єкти й анімований рух.

## Офіційні підстави

Unity зберігає серіалізовані поля під час перезавантаження коду; непідтримувані
структури потрібно відновлювати власним механізмом. Через вимкнене завантаження
сцени важливо мати ініціалізацію для повторних викликів життєвого циклу.
Джерела: [серіалізація Unity](https://docs.unity3d.com/6000.0/Documentation/Manual/script-serialization.html),
[перезавантаження сцени](https://docs.unity3d.com/6000.0/Documentation/Manual/scene-reloading.html).
