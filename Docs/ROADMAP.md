## Бачення гри

3D survival / life simulation про поступове зародження цивілізації на великому
процедурно згенерованому острові.

На старті острів переважно не заселений: ліси, вода, камінь, руда, природні
ресурси, тварини, потенційно печери. Гравець починає звичайним поселенцем майже
з нуля. NPC є повноцінними агентами, а не декорацією навколо гравця.

Світ повинен бути здатний розвиватися навіть без участі гравця:
NPC добувають ресурси, крафтять, працюють, будують, торгують, створюють бізнеси,
заявляють права власності, конкурують, мігрують і з часом утворюють поселення
та складніше суспільство.

Головний принцип: **життя має відбуватися саме, а гравець є одним з учасників цього світу.**

## Базові правила архітектури

1. **Один набір правил для Player і NPC.**
   Не створювати окремі PlayerInventory, PlayerCrafting або спрощені NPC-версії,
   якщо механіка за задумом доступна обом. Різниця — хто обирає дію: гравець чи AI.

2. **Матеріальна економіка.**
   Товар не виникає з нічого. Дерево повинно бути зрубане, колода отримана,
   дошки виготовлені, товар переданий або проданий, гроші переходять між
   конкретними власниками.

3. **Автономність NPC.**
   NPC оцінює потреби, навички, доступні ресурси, роботу, прибуток, відстань
   і ризики та самостійно обирає доцільні дії.

4. **Світ має стан і наслідки.**
   Вирубаний ліс зникає та відростає за правилами, родовища виснажуються,
   будинки мають власника й можуть бути продані, зруйновані або знищені.

5. **Survival доповнює гру, а не перетворює її на рутину.**
   Голод і спрага є базовими потребами. Температура, одяг, травми та інші
   системи додаються поступово, коли вони створюють цікаві рішення.

6. **Реалістичні причинно-наслідкові зв'язки, але прискорений ігровий час.**
   Реальні роки очікування не потрібні. Наприклад, дерево може вирости приблизно
   за кілька ігрових днів.

7. **Майно не зникає магічно.**
   Інвентар і кошти належать конкретному агенту. Після смерті NPC його предмети
   та гроші залишаються у світі й можуть бути забрані. На пізнішому етапі поверх
   цього додаються спадщина, право власності, крадіжка, злочин, свідки й репутація.

8. **Стандартні системи можна адаптувати з готових рішень.**
   Навігація, UI інвентарю, діалоги, анімаційна інфраструктура, vegetation та
   інші неунікальні системи можуть використовувати ліцензовані сторонні рішення.
   Власними залишаються ядро симуляції, економічні правила, автономні рішення
   агентів та інтеграція всіх систем в один світ.

### M1 — Universal Agent Foundation — CURRENT

Мета: припинити розвивати героя як окрему систему й створити фундамент,
яким надалі однаково користуються Player і NPC.

- Універсальний ItemDefinition / item catalog.
- Універсальний Inventory для Player, NPC, контейнерів, бізнесів і складів.
- Stack / quantity / transfer між inventory.
- Account / wallet ownership без створення нових грошей.
- Універсальні потреби: спочатку hunger і thirst.
- Generic action / command layer для дій над світом.
- Перша реальна транзакція героя через існуючу Economy.
- Купівля, перенесення та споживання хліба.
- Смерть агента не знищує його майно: inventory і гроші переходять у lootable state.
- Базова підтримка first-person з перспективою перемикання first/third person.
- Повне збереження стану героя та нових універсальних компонентів.

**Gate M1:** герой може мати гроші, купити реальний товар у бізнесу,
отримати його в універсальний inventory, спожити його для задоволення потреби,
а той самий inventory/account API може використовувати NPC.

Для завершення всього M1 також перевірити Save/Load та міграцію старих збережень,
базові спільні needs, first-person і збереження майна при переході агента в мертвий стан.
Цей перехід спочатку тестується як стан ядра, без зброї та повної бойової системи M9.
Майно контейнера тіла не дублює майно агента; кошти бізнесу відокремлені
від особистого гаманця власника. Підсистеми можна завершувати малими комітами.

### M2 — Resources, Tools & Crafting Vertical Slice

Мета: перша фізична виробнича система поза поточним зерно → хліб.

Перший ланцюжок:

`Tree → Log → Plank / Firewood / Stick`

- ResourceNode як універсальна сутність світу.
- Дерева як ресурси, а не тільки декорація.
- Harvest action.
- Базова сокира як вимога для рубання.
- Pickup / transfer отриманого ресурсу до inventory.
- Універсальний Recipe.
- Workstation / tool requirements.
- Колода → дошки.
- Колода → дрова.
- Палиці як окремий матеріал.
- Час виконання дії.
- Прості правила відновлення лісу.
- API працює для Player і NPC.

На цьому етапі інструменти можуть не мати durability, quality та складної прогресії.

**Gate M2:** і Player, і тестовий NPC можуть пройти один і той самий ланцюжок
`дерево → колода → матеріал` без спеціального коду лише для одного типу агента.

### M3 — Survival & Daily Life

- День / ніч.
- Початкова ціль: 48 реальних хвилин на одну ігрову добу.
- Hunger.
- Thirst.
- Їжа та вода як реальні items/resources.
- Сон / відпочинок після перевірки базового циклу.
- Особистий розклад агента замість глобальної однакової фази для всіх.
- AI планує роботу навколо базових потреб.
- Базовий respawn гравця.
- Температура, холод, одяг і травми — наступний шар, а не блокер M3.

**Gate M3:** агент може автономно пережити кілька днів, працюючи та задовольняючи
базові потреби через ті самі системи, що й гравець.

### M4 — Autonomous Work & Skills

- Універсальна система skills.
- NPC враховує навички під час вибору професії та задач.
- Робота — не лише employerId, а набір реальних виконуваних дій.
- Оцінка NPC: потреба → можливості → прибуток → навички → відстань → вибір.
- Самостійна зміна роботи.
- Базова ефективність від skill level.
- Пізніше: quality, durability, repair і рівні інструментів.

Навігацію підключати за потребою вже під час M2–M4: тести дерева, робочого
місця і доступу до ресурсів потребують досяжних маршрутів. Великий острів M5
не є умовою першого робочого прикладу; перевірений малий світ зберігається.

**Gate M4:** NPC без скриптованого сценарію сам знаходить економічно доцільну
роботу та реально виконує дії, з яких виникає товар.

- Водні зони та/або річки.
- Камінь.
- Рудні родовища.
- Придатні для забудови території.
- Resource spawn rules.
- Зони природного відновлення лісу.
- Якщо зона повністю втратила дерева, природне відновлення може зупинитися;
  посадка дерева дозволяє відновити ліс.
- Орієнтовний ранній темп росту дерева — кілька ігрових днів.
- Родовища мають кінцевий запас.
- Печери — опціонально після стабілізації генерації.
- Seed для відтворюваних світів.
- Save/Load зміненого стану процедурного світу.

**Gate M5:** нова гра створює відтворюваний необжитий острів з достатніми

## Контрольні сценарії розвитку

1. **Economic loop:** агент заробив → купив → отримав item → спожив.
2. **Resource loop:** дерево → колода → дошки/дрова → використання або продаж.
3. **Autonomy loop:** NPC сам знайшов вигідну діяльність і виконав її.
4. **Construction loop:** ресурси → будівництво → власність → використання.
5. **Civilization loop:** необжитий світ → поселення → бізнеси → конкуренція.
6. **Death loop:** смерть агента → inventory і гроші лишилися → loot / inheritance / ownership consequences.
7. **Observer test:** Player нічого не робить, а світ продовжує жити й розвиватися.

## Підтвердження поточного фундаменту

28 058 тверджень перевірок ядра, включно зі 100-денними сценаріями, проходять.
Після розділення presentation layer: 179 Unity-перевірок, включно з reload,
